# test-task-etolegko-pro

Консольный скрипт на Python для замера скорости скачивания.

Скрипт делает **10 последовательных запросов** к указанному адресу, на каждый
дожидается полного ответа (тело читается до конца), затем считает среднее время
запроса, общий объём скачанных данных и печатает скорость скачивания.

## Требования

- Python **3.10+**
- Для запуска скрипта внешних зависимостей нет — только стандартная
  библиотека (`http.client`), `pip install` не нужен.

## Запуск

```bash
git clone https://github.com/Dusmatoff/test-task-etolegko-pro.git
cd test-task-etolegko-pro
python speedtest.py <URL>
```

Пример (тестовый файл 10 МиБ):

```bash
python speedtest.py https://proof.ovh.net/files/10Mb.dat
```

> На Linux/macOS вместо `python` может понадобиться `python3`.

### Параметры

| Параметр            | По умолчанию | Описание |
|---------------------|--------------|----------|
| `url`               | —            | Адрес для скачивания (`http://` или `https://`) |
| `-n`, `--count`     | `10`         | Количество замеряемых запросов |
| `-w`, `--warmup`    | `0`          | Прогревочные запросы перед замером, в статистику не входят |
| `-k`, `--keep-alive`| выкл.        | Переиспользовать одно соединение для всех запросов |
| `-r`, `--retries`   | `2`          | Повторов при сетевой ошибке, оборванном ответе, 429 и 5xx |
| `--retry-delay`     | `1`          | Начальная пауза перед повтором (с), дальше удваивается: 1, 2, 4… |
| `-u`, `--units`     | `mbit`       | Единица скорости: `mbit` — Мбит/с, `mbyte` — МБ/с |
| `--json`            | выкл.        | Вывести результат в JSON |
| `-t`, `--timeout`   | `30`         | Таймаут сокета в секундах |
| `-h`, `--help`      |              | Справка |

Примеры:

```bash
# Чистая пропускная способность: 1 прогрев + одно соединение на все запросы
python speedtest.py https://proof.ovh.net/files/10Mb.dat -w 1 -k

# Скорость в МБ/с
python speedtest.py https://proof.ovh.net/files/10Mb.dat -u mbyte

# JSON для скриптов и мониторинга (прогресс уходит в stderr)
python speedtest.py https://proof.ovh.net/files/10Mb.dat --json > result.json
```

## Единицы измерения

- **Время** — секунды (с).
- **Объём** — десятичные единицы: 1 КБ = 1 000 байт, 1 МБ = 1 000 000 байт.
  Точное число байт печатается рядом в скобках.
- **Скорость** — по умолчанию **Мбит/с** (мегабиты в секунду,
  1 Мбит = 1 000 000 бит): в них обычно указывают скорость интернет-канала
  провайдеры и сервисы вроде speedtest. С `--units mbyte` — **МБ/с**
  (мегабайты в секунду); 1 МБ/с = 8 Мбит/с.

## Как считается

Время каждого запроса разбито на три этапа:

| Этап | Что входит |
|------|------------|
| **соединение** | DNS + TCP + TLS. С `--keep-alive` — только в первом запросе, дальше 0 |
| **ожидание** | от отправки запроса до получения заголовков ответа (TTFB), включая редиректы |
| **скачивание** | чтение тела ответа до последнего байта |

- **Время запроса** = сумма трёх этапов.
- **Среднее время** = сумма времён успешных запросов / их число.
- **Объём** — сумма байт тела ответа по всем успешным запросам (без HTTP-заголовков).
- **Скорость скачивания** = общий объём / суммарное время запросов — то, что
  видит пользователь, включая задержки сети.
- **Только тело ответа** = общий объём / суммарное время скачивания тела —
  «чистая» пропускная способность канала без накладных расходов на соединение
  и ожидание. Разница между двумя скоростями особенно заметна на маленьких
  файлах, где соединение занимает большую часть времени.

Чтобы получать реальный файл, а не закэшированный ответ, скрипт отправляет
заголовки `Cache-Control: no-cache` и `Accept-Encoding: identity` (без сжатия —
считаются именно байты файла). Редиректы (301/302/303/307/308) отслеживаются,
до 5 подряд.

## Ошибки и повторы

- **Повторяются**: сетевые ошибки и таймауты, оборванный ответ (получено меньше
  байт, чем в `Content-Length`), HTTP `429` и `5xx`. Пауза растёт
  экспоненциально от `--retry-delay`; если сервер прислал `Retry-After`,
  скрипт ждёт столько, сколько он просит (но не больше 60 с).
- **Не повторяются**: остальные `4xx` (например, `404`), ошибки сертификата,
  слишком много редиректов.
- Неудавшийся запрос **не останавливает** замер: статистика считается по
  успешным запросам, а число неудачных показывается отдельно.

Коды завершения:

| Код | Когда |
|-----|-------|
| `0` | все запросы успешны |
| `1` | хотя бы один запрос не удался (если успешных нет — статистика не печатается) |
| `2` | неверные аргументы |
| `130` | прервано по Ctrl+C |

## JSON-вывод

С `--json` в stdout печатается только JSON, а прогресс и ошибки — в stderr,
поэтому вывод можно перенаправить в файл или передать другой программе.
Скорость указана в выбранной единице (`speed_unit`), время — в секундах.

```json
{
  "url": "https://proof.ovh.net/files/10Mb.dat",
  "count": 10, "warmup": 0, "keep_alive": false, "retries": 2,
  "connections_opened": 10,
  "requests": [
    {"number": 1, "ok": true, "retries": 0, "error": null, "bytes": 10485760,
     "connect_s": 0.235, "ttfb_s": 0.132, "download_s": 2.675, "total_s": 3.042}
  ],
  "summary": {
    "successful": 10, "failed": 0, "total_bytes": 104857600,
    "avg_time_s": 3.044, "avg_connect_s": 0.23, "avg_ttfb_s": 0.132,
    "avg_download_s": 2.682, "speed": 27.55, "download_speed": 31.28,
    "speed_unit": "Mbit/s"
  }
}
```

## Разработка

Тесты поднимают локальный HTTP-сервер и не ходят во внешнюю сеть: проверяются
подсчёт байт, тайминги, keep-alive, прогрев, редиректы, повторы и
`Retry-After`, обрыв ответа, текстовый и JSON-вывод, коды завершения.

```bash
pip install -r requirements-dev.txt
flake8 speedtest.py tests   # стиль PEP 8
mypy speedtest.py           # проверка типов (strict)
pytest -v                   # тесты
```

Эти же проверки запускает GitHub Actions на каждый push и pull request
([.github/workflows/ci.yml](.github/workflows/ci.yml)) на Python 3.10, 3.12 и 3.13.

## Ограничения

- Переменные окружения `HTTP_PROXY` / `HTTPS_PROXY` не учитываются — запросы
  идут напрямую.
- Некоторые сайты блокируют неизвестные клиенты (например, Wikimedia отвечает
  `429` из-за User-Agent). Для замера лучше брать прямую ссылку на файл с
  обычного хостинга или тестового сервера.
